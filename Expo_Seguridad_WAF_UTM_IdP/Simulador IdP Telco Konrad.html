Identity Provider - Telco Konrad

Identity Provider · OIDC / OAuth2

Un solo login para ID-TRUE, Validación Crediticia, RequestManager y CRM

Hoy cada sistema tiene su propio acceso. Con un IdP, asesores, el grupo de back de validación y clientes inician sesión una vez (OIDC con PKCE) y cada API solo valida el JWT firmado. El cliente obtiene el acceso seguro, personal e intransferible.

    Código real equivalente (Spring Boot y Angular)
    Spring Boot · application.yml
    spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://idp.telcokonrad.co/realms/telco
          audiences: api-requestmanager
    Spring Boot · SecurityConfig.java
    @Bean
SecurityFilterChain api(HttpSecurity http) throws Exception {
  http
    .authorizeHttpRequests(a -> a
      .requestMatchers("/api/fraude/**").hasRole("FRAUDE")
      .requestMatchers("/api/solicitudes/**").hasAnyRole("ASESOR", "CLIENTE")
      .anyRequest().authenticated())
    .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()));
  return http.build();
}
// Nota: mapear el claim "roles" a authorities con un
// JwtAuthenticationConverter para que hasRole funcione.
    Angular · app.config.ts (angular-auth-oidc-client)
    provideAuth({
  config: {
    authority: 'https://idp.telcokonrad.co/realms/telco',
    clientId: 'portal-documentos',
    redirectUrl: window.location.origin,
    responseType: 'code',          // Authorization Code + PKCE
    scope: 'openid profile offline_access',
    useRefreshToken: true,
    secureRoutes: ['https://api.telcokonrad.co/'],
  },
})
    Angular · uso del interceptor
    // El interceptor agrega el header automáticamente:
// Authorization: Bearer eyJhbGciOi...
this.http.get<Solicitud[]>('https://api.telcokonrad.co/api/solicitudes')
  .subscribe(s => this.solicitudes = s);
